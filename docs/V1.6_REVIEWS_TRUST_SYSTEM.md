# TalentFlow V1.6 — Reviews, Ratings & Trust System Documentation

## Executive Overview
TalentFlow V1.6 introduces a production-grade, verified **Reviews, Ratings & Trust System** seamlessly integrated into the existing TalentFlow Marketplace infrastructure. All reviews are backed strictly by real, server-validated marketplace relationships (Hired Job Applications, Course Enrollments, Completed Freelance Contracts). Zero mock, fake, or hard-coded ratings exist in the codebase.

  reviewId         String
  reporterUserId   String
  reason           String
  details          String?
  status           ReviewReportStatus @default(OPEN)

  resolvedByUserId String?

  REMOVED
}

enum ReviewReportStatus {

  DISMISSED

## 2. Review Eligibility Engine & Verified Badges

All review submissions undergo strict server-side relationship validation. The client payload cannot pass `verified: true`. Verification is computed on the backend:

1. **`EMPLOYER_TO_CANDIDATE`** (`Verified Hire`):
   - Reviewer must be an employer user.
   - Must own the job application where status is `HIRED` or `OFFERED` (or status history contains `HIRED`).
2. **`CANDIDATE_TO_EMPLOYER`** (`Verified Employer`):
   - Reviewer must be a candidate user.
   - Must own the application where status is `HIRED` or `OFFERED`.
3. **`STUDENT_TO_COURSE`** / **`STUDENT_TO_TRAINER`** (`Verified Student`):
   - Reviewer must have an active `Enrollment` record for the course/trainer.
4. **`CLIENT_TO_FREELANCER`** (`Verified Client`):
   - Reviewer must have a `COMPLETED` `ProjectRequest` contract with the freelancer.

## 3. Backend REST API Endpoints

| Method | Endpoint | Authorization | Description |
| --- | --- | --- | --- |
| `POST` | `/api/v1/reviews` | JWT (Verified User) | Create a new verified review |
| `GET` | `/api/v1/reviews/:id` | Public | Get single review |
| `PATCH` | `/api/v1/reviews/:id` | JWT (Author only) | Edit own review (BOLA Guarded) |
| `DELETE` | `/api/v1/reviews/:id` | JWT (Author/Admin) | Delete review |
| `GET` | `/api/v1/reviews/user/:userId` | Public | Get reviews for a candidate/employer/trainer + summary |
| `GET` | `/api/v1/reviews/course/:courseId` | Public | Get reviews for a course + summary |
| `GET` | `/api/v1/reviews/me/given` | JWT (Authenticated) | Get reviews submitted by current user |
| `GET` | `/api/v1/reviews/me/received` | JWT (Authenticated) | Get reviews received by current user |
| `POST` | `/api/v1/reviews/:id/report` | JWT (Authenticated) | Report an inappropriate review |
| `GET` | `/api/v1/admin/reviews` | JWT (Admin) | Admin list all reviews with status filters |
| `GET` | `/api/v1/admin/reviews/reports` | JWT (Admin) | Admin list all reported reviews |
| `PATCH` | `/api/v1/admin/reviews/:id/moderate` | JWT (Admin) | Admin moderate review status (`PUBLISHED`, `HIDDEN`, `REMOVED`) |
| `PATCH` | `/api/v1/admin/review-reports/:id/resolve` | JWT (Admin) | Admin resolve report (`RESOLVED`, `DISMISSED`) |

## 4. Security, BOLA & Privacy Controls
- **JWT Identity Isolation**: Reviewer identity is derived exclusively from JWT tokens. Client payload parameters (`reviewerUserId`, `verified`) are ignored/rejected.
- **BOLA Protection**: Users can only edit or delete their own reviews. Unauthorized mutation attempts trigger HTTP 403 Forbidden.
- **Privacy Preservation**: No personal PII (email addresses, phone numbers, resume URLs, S3 keys, private interview notes) is exposed in review endpoints.

---

## 5. Audit Logging, Notifications & Email Isolation
- **Audit Logging**: Admin moderation actions (`MODERATE_REVIEW`, `RESOLVE_REVIEW_REPORT`) are automatically logged in `AuditLog` via `AuditLogsService`.
- **Notifications**: When a user receives a new verified review, `NotificationsService` dispatches a system notification non-blockingly.
- **Email Resilience**: Transactional Resend emails execute asynchronously and never block review creation or database transactions.

## 6. Frontend Reusable UI Components
- **`StarRating`**: Accessible 1–5 star control supporting interactive selection and read-only star rendering.
- **`VerifiedReviewBadge`**: Renders `Verified Hire`, `Verified Employer`, `Verified Student`, or `Verified Client` badges.
- **`ReviewSummary`**: Displays aggregate score, total count, and 1–5 star percentage breakdown. Clean zero state handling ("No reviews yet").
- **`ReviewCard`**: Individual review card with author info, rating, comment, edit/delete actions, and report trigger.
- **`ReviewForm`**: Form modal/card for submitting or editing reviews.
- **`ReportReviewDialog`**: Report dialog with predefined categories (`Spam`, `Harassment`, `False/Misleading`, `Personal Information`, `Inappropriate Content`, `Other`).
- **`AdminReviewsPage`**: Admin moderation dashboard at `/admin/reviews`.
