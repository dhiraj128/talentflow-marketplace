## 1. New Features & Core Capability

### End-to-End Hiring Pipeline (`/employer/pipeline`)
- Interactive Kanban Board organizing candidates across 5 active stages: `Applied / Pending`, `Shortlisted`, `Interviewing`, `Offered`, `Hired`.
- Dedicated filter tabs for terminal states: `Rejected` and `Withdrawn`.
- Real-time funnel analytics reporting stage conversion percentages.
- Employer-private candidate evaluation notes modal.
- Employer-scoped candidate tagging system with custom colors.
- Candidate application status transition history log modal.

### Candidate Application Tracker (`/job-seeker/applications`)
- Visual status stepper displaying real-time application stage.
- Timeline detail modal displaying historical transition audit logs with timestamps and reasons.
- Candidate self-service application withdrawal modal (`PATCH /applications/:id/withdraw`).

### Server-Side State Machine & Security Infrastructure
- Strictly enforced stage transition matrix in backend (`state-machine.ts`).
- Immutable `ApplicationStatusHistory` audit table logging `fromStatus`, `toStatus`, `changedByUserId`, `changedByRole`, `reason`, `createdAt`.
- BOLA protection: Employer-private candidate notes are strictly filtered out from candidate API views (`notes` returns `[]`).
- IDOR protection: Candidates can only withdraw their own applications; employers can only alter status on applications under their own job postings.

### Extended Transactional Email & Notification Center Integration
- In-app notification creation for `SHORTLISTED`, `INTERVIEWING`, `OFFERED`, `HIRED`, `REJECTED`, and `WITHDRAWN` status events.
- Resend transactional email dispatches for candidate stage transitions with custom action links (`View Applications` / `View Interviews`).

## 2. Technical Changes & Database Migration

### Database Schema Updates (`prisma/schema.prisma`)
- `enum ApplicationStatus`: Added `APPLIED` and `WITHDRAWN`, retaining legacy `PENDING` for backward compatibility.
- New Table `ApplicationStatusHistory`: Foreign keys to `Application` and `User` with index `(applicationId, createdAt)`.
- New Table `EmployerCandidateNote`: Foreign keys to `Application` and `EmployerProfile`.
- New Table `CandidateTag` & `ApplicationTagAssignment`: Employer-scoped tag storage.
- Migration Script: `20260731000000_v1_1_hiring_pipeline/migration.sql` (zero destructive SQL, zero table drops, zero data mutations).
