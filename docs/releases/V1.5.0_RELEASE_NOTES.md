## Highlights & Communication System Architecture

### 1. Existing Messaging Audit & Upgrade
- Reused existing `Conversation` and `Message` Prisma models, `MessagesController`, `MessagesService`, and frontend routes.
- Applied forward-only migration `20260731160000_v1_5_communication_center/migration.sql` (`0` table drops, `0` truncations).

### 2. Server-Side Relationship Authorization Policy
- Candidate ↔ Employer messaging is permitted **ONLY** when a valid hiring relationship exists (active `Application`, accepted `CandidateInvitation`, `Interview`, or `JobOffer`).
- Arbitrary candidate messaging via Talent CRM without a hiring relationship is rejected with `403 Forbidden`.

### 3. BOLA / IDOR Security Protection
- `senderId` derived strictly from authenticated JWT (`user.sub || user.userId`).
- Every query verifies conversation participation (`participant1Id` or `participant2Id`).
- Unauthorized requests from Candidate B or Employer B return `403 Forbidden`.

### 4. Real-Time Unread & Notification System
- Added `GET /api/v1/messages/unread-count` for global header badge count.
- Auto-marks messages read and updates `lastRead` timestamps upon viewing.
- Dispatches in-app notifications to recipient upon message arrival.

### 5. Multi-Browser & Responsive Playwright E2E Matrix
- Executed Playwright E2E matrix across Chromium, Firefox, WebKit and 8 viewport dimensions (`360x800` to `1920x1080`).
- Achieved **96 / 96 PASS** rate with 0 horizontal page overflow.

### 6. Zero Mock Data Compliance
- Automated zero-mock production guard (`scripts/audit-production-mocks.js`) verified 0 prohibited business mock violations across all messaging pages.
