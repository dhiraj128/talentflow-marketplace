## 1. Overview
TalentFlow Marketplace V1.5 introduces a production-grade, secure, relationship-authorized Communication Center and Messaging System built on top of baseline `v1.4.0`.

## 3. Communication Policy & BOLA Security

### Server-Side Relationship Validation
Candidate ↔ Employer messaging is permitted **ONLY** when a legitimate relationship exists:
- Active `Application`
- Accepted `CandidateInvitation`
- Scheduled or completed `Interview`
- Extended or accepted `JobOffer`
- Direct Admin intervention

Arbitrary messaging of discoverable candidates via Talent CRM without a hiring relationship is rejected with `403 Forbidden`.

### BOLA / IDOR Protection
- `senderId` is derived strictly from authenticated JWT (`user.sub || user.userId`).
- Every query verifies that current user equals `participant1Id` or `participant2Id`.
- Changing `conversationId` or `userId` in URL parameters or request body cannot bypass authorization.

---

## 4. API Endpoints

- `GET /api/v1/messages/conversations`: Returns user conversations with last message and unread count.
- `POST /api/v1/messages/conversations`: Starts a relationship-validated conversation.
- `GET /api/v1/messages/unread-count`: Returns global unread message count badge.
- `GET /api/v1/messages/conversations/:id`: Fetches conversation messages, auto-marks messages read, and generates pre-signed attachment download URLs.
- `POST /api/v1/messages`: Validates max content length (5000 chars), persists message to PostgreSQL, updates conversation timestamp, unarchives participants, and dispatches in-app notification.
- `PATCH /api/v1/messages/conversations/:id/archive`: Participant-specific archiving.
- `PATCH /api/v1/messages/:id/read`: Marks message read.
