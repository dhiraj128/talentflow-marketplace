# TALENTFLOW MARKETPLACE V1.1 — END-TO-END HIRING PIPELINE & CANDIDATE APPLICATION TRACKER

**Release Version**: V1.1.0  
**Feature Scope**: End-to-End Hiring Lifecycle (`APPLIED` $\rightarrow$ `SHORTLISTED` $\rightarrow$ `INTERVIEWING` $\rightarrow$ `OFFERED` $\rightarrow$ `HIRED`, with `REJECTED` and `WITHDRAWN` terminal states).  

---

## 1. Executive Summary

TalentFlow Marketplace V1.1 transforms the basic candidate application workflow into a production-grade, end-to-end hiring pipeline with:
- Server-side state machine transition enforcement.
- Immutable `ApplicationStatusHistory` audit trail.
- Employer-private candidate notes (`EmployerCandidateNote`).
- Employer-scoped candidate tags (`CandidateTag`).
- Candidate application withdrawal workflow (`PATCH /applications/:id/withdraw`).
- Responsive Employer Hiring Pipeline & Kanban Board (`/employer/pipeline`).
- Visual Candidate Application Tracker timeline (`/job-seeker/applications`).
- Extended Notification Center and Resend transactional email events.

---

## 2. Server-Side State Machine & Canonical Lifecycle

```
APPLIED / PENDING
      │
      ├──> SHORTLISTED ──> INTERVIEWING ──> OFFERED ──> HIRED (Terminal)
      │         │                 │            │
      └─────────┴─────────────────┴────────────┴─────> REJECTED (Terminal)
      │
      └──────────────────────────────────────────────> WITHDRAWN (Candidate Terminal)
```

### Transition Validation Rules (`state-machine.ts`)
- **Allowed Next Stages**:
  - `APPLIED` / `PENDING` $\rightarrow$ `REVIEWING`, `SHORTLISTED`, `REJECTED`, `WITHDRAWN`
  - `SHORTLISTED` $\rightarrow$ `INTERVIEWING`, `OFFERED`, `REJECTED`, `WITHDRAWN`
  - `INTERVIEWING` $\rightarrow$ `OFFERED`, `HIRED`, `REJECTED`, `WITHDRAWN`
  - `OFFERED` $\rightarrow$ `HIRED`, `REJECTED`, `WITHDRAWN`
- **Terminal States**: `HIRED`, `REJECTED`, `WITHDRAWN` (no further transitions permitted).

---

## 3. Database Schema Evolution & Forward Migration

Added models to `prisma/schema.prisma`:
- **`ApplicationStatusHistory`**: Logs `fromStatus`, `toStatus`, `changedByUserId`, `changedByRole`, `reason`, `createdAt`.
- **`EmployerCandidateNote`**: Employer-private notes per candidate application.
- **`CandidateTag`** & **`ApplicationTagAssignment`**: Employer-scoped tag management.

---

## 4. Security & Role Isolation (RBAC & BOLA/IDOR)

- **Employer Isolation**: Employer A can ONLY view, update status, add notes, or assign tags to candidate applications submitted for Employer A's job postings (`application.job.employerId === employer.id`).
- **Candidate Isolation**: Candidates can ONLY view their own application timelines and withdraw their own applications. Employer-private candidate notes and internal tags are strictly filtered out from candidate API responses.

## 5. User Interface Extensions

### Employer Hiring Pipeline & Kanban Board (`/employer/pipeline`)
- Columns: `Applied / Pending`, `Shortlisted`, `Interviewing`, `Offered`, `Hired`.
- Filter Tabs for `Rejected` and `Withdrawn`.
- Live Conversion Metrics: Applied $\rightarrow$ Shortlist %, Shortlist $\rightarrow$ Interview %, Interview $\rightarrow$ Offer %, Offer $\rightarrow$ Hire %.
- Actions: Transition stage buttons, Private notes modal, Candidate tag assignment, History timeline modal.

### Candidate Application Tracker (`/job-seeker/applications`)
- Visual Stepper: Applied $\rightarrow$ Shortlisted $\rightarrow$ Interviewing $\rightarrow$ Offer $\rightarrow$ Hired.
- View Timeline Modal showing exact timestamps and transition reasons.
- Candidate Withdraw Application modal with reason capture.
